# 8111 本地接口 · 使用经验

> 本项目(黑名单助手 + 跑图线路测试器)在开发中通过**实测**得到的 8111 使用经验汇总。
> 接口的原始字段参考(第三方社区文档)见 `docs/wt8111/`;进出场与昵称相关结论见
> `docs/8111自定义对局实测分析.md`;跑图测试器的数据来源见 `docs/跑图线路测试器.md` 第 6 节。

---

## 1. 基本信息

- 地址: `http://localhost:8111`,**游戏启动即监听**,无需任何设置(战争雷霆内置本地服务);
- 除 `/map.img` 返回图片外,其余端点均返回 JSON;
- 中文/UTF-8,响应头带 `Access-Control-Allow-Origin: *`;
- 端口仅在**游戏运行期间**可用;退出游戏即失效。

---

## 2. 端点清单(实测)

| 端点 | 内容 | 本项目用途 |
|---|---|---|
| `/indicators` | 载具与仪表(`type` `speed` `gear` `rpm` `army` …) | 载具名、速度 |
| `/map_obj.json` | 地图对象数组(玩家/地物/战区) | **玩家坐标**、朝向 |
| `/map.img` | 地图卫星图(**JPEG**) | 地图底图 |
| `/map_info.json` | 地图几何与网格(含 `valid`) | **进出场判定**、坐标换算 |
| `/mission.json` | 任务状态与目标 | 辅助(见 §3.4) |
| `/hudmsg` | 击杀/伤害消息 | 昵称收集 |
| `/gamechat` | 对局聊天 | 昵称收集 |
| `/state` | 空战仪表 | 陆战返回 `{"valid": false}`,不适用 |

---

## 3. 关键实测结论

### 3.1 玩家坐标(最容易踩坑的一点)

玩家出现在 `/map_obj.json` 里,但**靠 `icon == "Player"` 标识,不是靠 `type`**:

```json
{"type":"ground_model","icon":"Player","x":0.536519,"y":0.181914,"dx":-0.673497,"dy":0.73919}
```

- `type` 是**载具类别**(陆战 `ground_model`,空战 `aircraft`),不是 `"player"`;
- `x`/`y` 为 **0~1 归一化坐标**,`dx`/`dy` 为单位方向向量(可画朝向);
- 同一次实测中 `map_obj.json` 共 54 个对象:玩家 1 个,其余是 `respawn_base_tank`(40)、
  `airfield`(6)、`capture_zone`(3)、`respawn_base_fighter`(2)、`respawn_base_ucav`(2)
  → **必须按 `icon` 精确筛选**,绝不能"取唯一一个带 x/y 的对象";
- 地物(如 `airfield`)用 `sx/sy/ex/ey` 表示线段,数值**可以超出 0~1**(位于地图外);
- **自定义房间同样能取到玩家坐标**(2026-10-06 实测),此前"自定义对局无玩家对象"的说法
  只对*其他玩家*成立。

### 3.2 地图图片与坐标换算

- `/map.img` 实测为 **JPEG**,**2048 × 2048**;
- 与 `/map_info.json` 的 `map_max`/`map_min`(实测 `[2048,2048]` / `[0,0]`)一致;
- 换算:**像素 = 归一化坐标 × 图片尺寸**,方向与图片一致(y 向下),无需翻转;
- `map_info.json` 实测字段:`grid_size` `grid_steps` `grid_zero` `hud_type`
  `map_generation` `map_max` `map_min` `valid`;
- ⚠️ 打包分发时**必须保留 Qt 的 JPEG 解码插件**(`qjpeg.dll`),否则地图无法显示
  (见 `tools/trim_qt.py --keep-imageformats`)。

#### 战局外返回的是 "?" 占位图(2026-10-06 实测)

**不在对局/试车场**时 `/map.img` **依然 200 且内容合法**,但不是地图:

| 项 | 值 |
|---|---|
| 格式 / 大小 | `Content-Type: image/png`,**1519 字节** |
| 尺寸 | **128 × 128** |
| SHA1 | `ab516d02191d001d809253c346e8e3f93e13f136` |
| 内容 | 纯灰阶,仅 6 种颜色(64/68/72/109/115/128),中心 `(128,128,128)` |
| 外观 | 深灰底 + 浅灰 "?" |
| 同时 | `/map_info.json` = `{"valid": false}` |

存档样本:`docs/assets/8111_map_placeholder.png`。

判据建议:

- **优先用 `/map_info.json` 的 `valid`** 判进出场(1 个字段即可);
- `/map.img` 的**字节 SHA1 可直接当地图身份**:内容一变就是换图 ——
  8111 不提供地图名,这是唯一可靠的“地图 ID”;同时也别忘了过滤上面的占位图。

### 3.3 载具名(`/indicators` 的 `type`)

实测形如:

```
tankModels/germ_leopard_2a4_pzbtl_123
```

即 `xxxModels/` + 国家前缀 + 型号 + 部队/改型后缀。显示前建议:
先剔除 `xxxModels/` 前缀,再按需求美化(本项目: `Leopard 2A4 Pzbtl 123`)。

### 3.4 进出场判定

- `/mission.json` 的 `status` 在**机库 / 对局 / 退出后**都恒为 `"running"` → **完全不可用**;
- **唯一可靠信号**:`/map_info.json` 含完整地图数据(`valid` 非 `false` 且有 grid/map 字段)
  ⇒ 在地图内(对局或试车场);返回 `{"valid": false}` ⇒ 已回到机库。
- ⚠️ 只判 `/map.img` 是否 200 **不够** —— 战局外它也会返回 200(内容为 "?" 占位图,
  见 §3.2),必须比对指纹或看 `map_info.valid`。

### 3.5 陆战 / 空战差异

| | 空战 | 陆战 |
|---|---|---|
| `/state` | 可用(姿态/发动机等) | `{"valid": false}`,不可用 |
| `/indicators` | 姿态、发动机、燃油… | `army`/`type`/`stabilizer`/`gear`/`rpm`/`crew_*` 等约 20 个键 |
| `/map_obj.json` | 玩家 `icon=="Player"` | 玩家 `icon=="Player"`(`type=ground_model`) |
| **`speed` 精度** | **有小数**(实测最多 6 位, 如 `89.072037`) | **整数**(实测 4000+ 样本无一小数) |

`speed` 单位为 km/h。陆战返回的就是**整数**(游戏内仪表同样取整, JSON 里写成 `0.000000` 只是格式化);
空战则是高精度浮点。因此显示速度建议**自适应**:有小数才显示小数位。

### 3.6 地图名:**8111 拿不到**(2026-10-06 实测)

想给地图起名/自动识别地图时会先想“接口里应该有地图名”, 结论是**没有**:

- 逐端点看过:`/map_info.json`(只有 grid/hud_type/map_generation/valid)、`/mission.json`
  (只有 `objectives` 文本, 如“占领并守住战区”)、`/state`、`/indicators`、`/map_obj.json`、
  `/hudmsg`、`/gamechat` 都**没有**地图名或任务名;
- 8111 **官方页面自己**只请求 `/map.img`、`/map_info.json`、`/map_obj.json`、`/mission.json`
  (把 `/` 拉下来数一遍即可确认), 也没有地图名接口;`/map.json`、`/mission_name.json`、
  `/battle.json` 等常见猜名端点都是 404;
- 客户端本地文件也没有:游戏目录 `.game_logs/*.clog` 是二进制/压缩(搜常见词 0 命中),
  `Documents/My Games/WarThunder/Saves/**/*.blk` 里搜 `levels/` 里的 164 个地图名(如
  `avg_*`/`air_*`)**一个都没出现**。

⇒ 只能**自己做地图身份**:用 `/map.img` 的**字节哈希**(sha1 前 12 位)当 map_key,
图片存本地缓存, 名字交给用户起一次(本项目: 菜单「地图」→「地图管理」)。
想自动识别就得维护“图片哈希 → 地图名”的对照表(社区共享或人工标一次)。

## 4. 性能与可靠性注意事项

- **前台运行 ~40-50Hz、rtt ~10ms**(空战/陆战一致,高频采样脚本实测 10ms 间隔可得约 46Hz)。
- **数据真实更新率约 25Hz**(2026-10-06 统计 `speed_log_g1_run4.csv` 2072 样本):
  `rpm` 变化间隔 p50 = **40 ms** → 数据本身約每 40 ms 才更新一次;
  实测 46Hz 采样时**每个数据点被重复采約 1.85 次**。
  ⇒ **采样间隔取 40 ms 即与数据源匹配**, 再快只是重复采样。
  (注意: 不能用 `speed`/`gear` 衡量刷新率 —— 陆战 `speed` 是整数、`gear` 极少变,
  实测变化间隔分别只有 93 ms / 500 ms; `rpm` 是连续量, 才可靠。)
- ⚠️ **游戏失焦 / 切到后台时 8111 会显著变慢甚至请求超时**
  → **性能测试必须在游戏前台进行**,否则会得出"只有 0.5Hz"这种错误结论(2026-10-06 踩过)。
- 每轮完整刷新需要 **2 次请求**(`/indicators` + `/map_obj.json`),实测约 20ms ⇒ 理论上限 ~50Hz;
  想再快只能减少请求数(例如把 `/indicators` 降频,坐标每帧取)。
- `timeout` 建议 **0.3 ~ 1.0 秒**:8111 正常 rtt 仅 ~10ms,超时值设太大会让一次卡顿拖垮整轮轮询。
- `/map.img` 约 **230KB+**,**不可每帧请求** —— 应按需/节流(本项目每 2 秒且内容变化才刷新)。
- 任何请求失败都应视作"未连接"优雅降级,**不要把异常抛给 UI 线程**。

### 4.1 提高轮询频率的实战做法(2026-10-06)

要让轮询真正跑到 40Hz,以下几点缺一不可(均已在 `route_recorder.py` 落实):

1. **用 `127.0.0.1` 而不是 `localhost`** — Windows 上 `localhost` 可能先解析到 IPv6(`::1`)
   再回退 IPv4,高频轮询下这笔开销很明显;实测脚本 `tools/probe_air_speed.py` 一直用 `127.0.0.1`。
2. **减少每轮请求数** — 单请求实测约 20ms,每轮 2 个请求上限就只有 ~25Hz。
   做法: `/map_obj.json`(坐标, 轨迹平滑的关键)每帧取; `/indicators`(载具/速度, 变化慢)
   **降频到每 4 帧一次** → 每轮平均约 1.25 个请求。
3. **大响应放独立线程** — `/map.img` 约 230KB,若在轮询线程里下载会周期性卡住整帧,
   应交给单独线程按需刷新(内容变化才更新界面)。
4. **超时取小值(0.5s)** — 8111 正常 rtt ~10-20ms;超时值过大会让一次偶发卡顿拖垮整轮。
5. **目标周期调度** — 不要"请求完再 sleep(固定间隔)", 那会把请求耗时叠加进去;
   应按"下一帧的目标时刻"算剩余等待(落后了就重置, 不累积滞后)。
