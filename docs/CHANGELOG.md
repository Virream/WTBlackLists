## 未发布

### 跑图线路测试器

- **A/B 队录制标记不再持久化**: 它只是“下次点录制录到哪一条”的临时指向,
  关掉软件就该忘掉(以前会写进 `routes.json`, 第二天点录制会莫名其妙录到旧条目上)。
  旧文件里的标记读入时一律忽略。
- **静止的车, 线尾比真实消失早最多 15 秒**(修): 采样只在移动时存点、静止时每 15 秒
  补一个心跳点, 收尾时又只在“位置变了”才补终点 —— 于是一直停着的车(防空车、
  部署好的发射车)线尾停在最后一次心跳上。实测西奈半岛那局两台**同时**被毁的发射车
  分别结束在 307.5s 和 316.6s, 差 9 秒就是这么来的。现在收尾无条件补到
  “最后一帧见到它的时刻”。
- **hudmsg 采集加了诊断日志**: 每次轮询记一行(取到几条、其中阵亡几条、游标变化),
  发现 id 跳跃(>60)时告警“环形缓冲区可能已滚动, 中间的阵亡会丢”。
  死亡时刻修正里“这一段没有他的阵亡”也会带上“本局共采到 N 条击毁消息”, 便于判断
  是数据没采全还是他真的没死。
- **分体防空(雷达车 + 发射车)**: 8111 会把同一玩家的每台车各上报一份(`Player` / `Radar` /
  `SAM`, 颜色都是“自己黄”), 所以三条线**各自录制、各自判死、各画一个叉**(实测 2026-10-23:
  雷达车被 AGM-88A 打掉时, 两台发射车在同一帧一起消失)。
  - 侧栏名字改用**第一个非 `Player` 的类别**(否则三条线全叫 “Player”, 分不清雷达车);
  - 死亡时刻修正只针对**最外层那条**(摄像机挂着的那台, 它阵亡后不消失、线会拖到录制结束);
    被它包住的发射车那几条本来就死得准, 不再当成“额外的命”(否则会算成“阵亡 3 次”)。
- **A/B 两队的战区颜色统一了**: 8111 的颜色是“站在观战者视角”的, A、B 是两次观战、
  视角相反 —— 以前两段快照混在一条时间轴上, 回放时同一个战区的颜色一会儿蓝一会儿红。
  现在时间轴每条都记下**是哪一次观战录的**(`side`), 回放取同一次观战的那批, 再按
  “两队各自重生点的颜色”重映射(`zones.decode_capture` 反解出
  `(端点, 端点, 进度)` 后用新调色板重算, 进度比例不变)。旧数据没有 `side` → 不动颜色。
- **战区占领动画改对了**: 8111 给战区的 `color` 不是“三种归属色”, 而是游戏自己算好的
  **占领进度混色**(中立白 → 蓝 / 白 → 红, 中途如 `#587EFD`、`#fc7E76`)。以前先归成
  蓝/红/白三档再上固定色, 进度全丢, 而且中途混色会被判成“中立”, 颜色会乱跳。
  现在**直接用 8111 的原色**, 于是“争夺时进度回落”“易手时先清空旧进度再涨新进度”
  “防守方在场时不动”这些规则自动就对了(游戏已经把结果算进颜色里)。
  另外 `zone_states` 的变化判据加了量化颜色, 回放也能看到进度在动。
- **放大到最大时满屏方块**: 底图只有一个分辨率, 双线性放大到 6~20 倍时, JPEG 里逐像素的
  噪点(草地最明显)被放大成一个个方块。现在按“每个源像素放大成几个屏幕像素”分档:
  < 2.5 倍用原图, 2.5~14 倍用降采样 2 倍的版本, ≥ 14 倍用降采样 3 倍的版本(盒式低通,
  噪点被平均掉)。档位图在换图时一次性建好, 稳态帧时间反而从 3.4 ms 降到 1.7~2.3 ms。
  对比工具: `tools/probe_map_quality.py`、`tools/probe_map_upscale.py`。
  (起初用的是“6 倍以上降 4 倍”, 实机看下来太糊 —— 2048² 地图 + 1264×720 窗口时满格
  实际只有 7 倍, 清晰度掉近一半; 已改成上面这组阈值。)

## 跑图线路测试器 v1.1.1(2026-10-22)

### 修复

- **回放中“所有路线卡一下”**: 战区状态混在轨迹层的内容指纹里, 于是每次占领/易手都
  把全部线路的几何重算一遍 —— 实测 67 条线 **239 ms/次**, 一局发生 9 次(用户报
  “播放中偶尔整片线路卡一下, 像是某条线的玩家阵亡要隐藏导致的”)。
  实测排除“死亡隐藏线路”(那一步只多 0.3~2 ms); 真正的原因是战区快照每帧都变。
  现在指纹拆成 **轨迹 / 图标 / 战区** 三级, 战区变化只换那几面菱形旗(亚毫秒):
  整层重建 9 次 → **0 次**, 单帧最慢 239 ms → **7.75 ms**, 平均 3.76 → 2.80 ms。
  核对工具: `tools/probe_playback_stutter.py`(逐帧把同步与提交分开计时)。

## 跑图线路测试器 v1.1.0(2026-10-22)

### 新增

- **A/B 队全局录制**: 两次独立观战, 把整局所有玩家的地面线路录下来, 分两队、按绝对
  时间轴同步回放; 支持边录边画、重录覆盖、标记 A/B 队录制目标。
- **阵亡时刻修正**: 用 `/hudmsg` 的击毁记录把“摄像机挂着那位玩家”的真实阵亡时刻补回来
  (其余玩家 icon 正常消失, 判死本来就准)。一条命一条线, 一局死几次就修几条;
  候选名单里 ★ = 每一条命都对上, ✔ = 能修其中几段, 灰 = 对不上。
  没有匹配到任何线路时保留黄色感叹号, 只要真修过就移除。
- **阵亡叉 / 回放光标点的颜色**改为跟随“该队重生点在地图上的颜色”
  (A/B 两次观战颜色是反的, 不能再写死 A 蓝 B 红)。
- **录制叠加层**: 录制时显示实际采样率、轮询频率、点数、标记数(菜单「设置 → 叠加层」)。
- **`/hudmsg` 边录边取**: 每 15 秒取一次增量, 避免环形缓冲区把前几分钟的击杀挤掉;
  同时识别两种阵亡文本(`击毁了` / `已被摧毁` = 弃车、淹死、坠毁)。
- **转弯半径**改为整数米 + `±x%` 一致度; **全局线路存储**改紧凑 JSON + gzip(716 KB → 100 KB 级)。
- **性能与内存**: 修复缩放/换图时场景对象累积(重生方块叠成一堆同心方框);
  重建图标只换图标层; 悬停命中改 numpy 批量; 缓存按“画面上还存在的线路”剪枝。

### 修复

- **全局线路的速度配色与单条轨迹不一致**: 原先全局线路固定以 120 km/h 为基准
  (看起来偏藍), 现改成与单条轨迹完全同一套规则(基准 = 这条线自己的最高速),
  同样的速度就是同样的颜色。
- **眼睛开关可能“一点就全灭”**: 重录/删除后 `_visible_lives` 里可能残留已不存在的
  线路 id, 导致“这一层当前亮不亮”的判断全错。现在每次刷新都会剪掉失效 id,
  开关只认真实存在的线路, 状态栏还会写明到底切换了哪一层(如“已隐藏「A 队」 15 条…”)。
- **全局录制时刷新率掉到 8Hz / 滚轮缩放卡顿**: "边录边画"最初每帧都把全部线路重画一遍
  (240 ms/帧)→ 改成**累加层**(每帧只补新段, 3.5 ms/帧); 缩放时先把旧图层按比例贴上去
  (270 ms → 5 ms), 停手 200ms 后再重建。
- **录制结束时反复报错弹窗**: `AttributeError: 'UnitLife' object has no attribute
  'zone_signature'` —— 选战区布局时没跳过全局线路, 每帧都抛一次。已用 `getattr` 兜住。
- **回放全局线路会崩**: 回放光标要读点的朝向, 而全局点没有 `dx/dy`,
  `point_at()` 已兼容。
- **不播放时滚轮缩放也卡**: 轨迹层的内容指纹里含了几何指纹, 于是**每滚一格**都要把
  全部轨迹重新栅格化(1920×1040 / 20 条线要 25~37ms, 连滚 6 格 245ms)。现在把内容与
  几何拆开 —— 缩放/改窗口时先把旧层**按比例贴上去**(1~2ms), 停手 200ms 后再重建一次;
  余量的容忍范围按缩放比放大(否则放大中途锚点一漂就重建), 离屏图回收复用。
  实测单格 6~10ms, 连滚 6 格 105ms。
  顺带修正了按比例贴图的偏移(`p.scale()` 会多出 `(余量+锚点)×(scale-1)`,
  放大 2 倍能偏两百多像素)与“改窗口后余量算错”的问题。
- **全局录制中途“线路突然断开、换个地方继续画”**: 观战中的玩家上了固定翼时, 8111 会把
  地图切成空战图, 同一批地面单位的坐标**整体被缩放 1/16 并平移** —— 帧间最近邻全部
  脱靶, 正在录的线就断了。现在用**静态地物(重生点/战区)当锚点**每帧反解相似变换,
  把坐标换算回录制开始时的地面坐标系(实测反解精确到 1e-5:
  `空战 = (陆战 + (8,7)) / 16`); 换算期间速度仍按地面图的边长算;
  换视角后的 5 秒内不判“被击毁”(那几秒消失更可能是看不见了)。
  坐标系一变还会写一行**交叉校验日志**, 把拟合尺度与 `/map_info.json` 的图框比对照
  (实测 `图框 65536/4096 = 16.0000× → 与拟合一致(差 0.00%)`)。
  核对工具: `tools/probe_frame_align.py`。
- **回放中途缩放后, 着色段画到一半就不再增长**(只有再缩放一下才显示):
  “几何变了就先按比例贴旧层”这套做法里, `_note_geom_change()` 被每帧调用
  (重建之前“当前几何 != 建层几何”每帧都成立), 而它会刷新“最后一次几何变化”的
  时间戳 —— 于是 `_geom_settle()` 永远以为“刚刚还在缩放”, 无限推迟重建, 画面就
  永远停在按比例贴的旧图上。现在只在几何**再一次真的变了**时才刷新时间戳。

### 新增

- **回放新增两个“被击毁”显示选项(默认勾选)**:
  - **被击毁后路线变暗**: 线路对应的玩家阵亡后, 整条线变成半透明纯灰(不再按速度着色);
  - **被击毁标记**: 在阵亡位置(线路末端)画一个小叉, 与回放光标白点差不多大;
    **A 队 = 蓝、B 队 = 红**(按 `UnitLife.side` 区分, 旧数据按所在分组补);
  - 判定只看 8111: 这条线的 icon 突然消失、而那一刻场上还有别的单位 → 算阵亡;
    **全场一起消失**(回到车库/录制结束)不算 —— 有人整局一次不死, 不能画叉;
  - 阵亡后不再画白点光标(已经没有“当前位置”); 标记在回放越过阵亡时刻后才出现;
  - 旧录制没有这个信息, 读取时按“结束得比整局末尾早 10 秒以上”推断。
- **A/B 时间轴诊断**: 两队都是“抓到第一辆载具 = 0 点”, 每次全局录制结束会写一行
  `全局录制 时间轴: A 队 28 条 0~522.0s | B 队 36 条 0~523.5s | 结尾差 -1.5s`,
  用来看两次录制对不对得上。⚠ 时间按**真实时钟**计: 两次录制请都从同一位置开始、
  保持 **1× 且不要暂停**, 否则两队的轴会被拉长/压短(8111 不提供战斗时钟)。
- **全局录制(整局所有玩家的线路)**: 侧栏"存放路线的那一级"末尾多出一种条目,
  名字就是录制时间; 展开分 `A 队 / B 队`, 组内按时间正序。
  - 录制按钮用竖线分区: 左 = 单条线路(开始/结束/标记), 右 = `A 队录制` /
    `B 队录制` / `停止 A/B 队录制`;
  - 点按钮时通常还在等待部署, 程序挂着等**第一名玩家重生**才定 0 秒;
    demo 播完回到车库(8111 换占位图 / 全场无单位 3 秒)会自动停止;
  - 录制期间**锁定地面底图**, 有人上飞机也不切成空战地图;
  - 只录地面单位, 空中单位全部跳过(实测侦察无人机的 icon 与固定翼相同, 无法区分);
  - **记录速度并按速度配色**, 与单条轨迹同一套画法; 录制过程中**边录边画**;
  - 全局线路**可以回放**: 选中条目就播它下面的全部线路, 只选中几条就只播那几条;
  - 出生保护不再记录(重生靠“消失即结束”自然拆线);
    **不记朝向**, 也不受"以速度从零变化时刻作为起始时间点"影响;
  - 右键全局条目可**标记为 A/B 队录制目标**(有标记就录到那条、没有就新建),
    已录过的会先问是否清空重录; 支持显示/隐藏与删除(删除需确认);
  - 8111 不给玩家名, 线路按"出现时间 + 载具类别"显示, 同一人上飞机/换车会断成两条线。

### 文档

  (`aircraft Player` = 摄像机所在无人机 + `ground_model` = 本体地面车), 且会带出
  坐标 2.9~3.4 的远处 AI 防空 —— 全局录制必须按 `icon == "Player"` 认摄像机并过滤越界坐标。

## 2.0.5 / 1.0-1.1.4(2026-10-10, 测试阶段)

> ⚠️ 测试阶段, 功能与数据格式可能调整。

### 修复

- **进出对局完全按 8111 地图图片判定**: 真地图 = 在对局; 占位图 / 不是图片 = 在车库。
  不再依赖会残留的 `map_info` / `mission`(退出对局后它们还会保留上一局内容, 导致叠加层
  在机库里多显示一段时间)。
- **只认"新增消息"**: `/hudmsg` 消息 `id` 跨局只增不重置 → 启动时先建游标基线,
  上一局的人、以及软件启动前就在窗口里的 ID 都不会被算进本局; 加载期(地图图片还没出现)
  的新击杀会立刻判定进局并上报。
- **消息轮询降到 3 秒一次**: 每秒轮询 `/hudmsg` + `/gamechat` 时, 游戏偶尔会漏发 HUD 消息
  (实测"软件一开, 刚进试车场打掉的第一辆靶车有时没有记录"), 降到 3 秒后消失。
  游标不推进, 消息不会丢, 只是最多晚 3 秒被看到。
- **回库立刻收工**: 8111 明确回答"占位图 / 不是图片"就立刻清空本局收集, 叠加层 1 秒内隐藏
  (以前要等连续两次确认 + 5 秒活动宽限)。
- **1.0 修掉 `localhost`**: 之前整个 1.0 都在用 `localhost`(Windows 会先试 IPv6, 8111 只监听
  IPv4 → 多一轮解析/重试, 偶发超时), 改为 IP 直连 `127.0.0.1`。
- **网络健壮性**: 请求超时 1 → 2 秒; 单次请求失败不再当成"没有新消息 / 已断开"(保留游标,
  连续 3 次才按断线处理); 请求失败即丢弃连接池(换地图后旧连接会变成死连接, 复用会卡到超时)。

### 其它

- 昵称匹配改为**区分大小写**(游戏里同一串字母大小写不同就是两个不同玩家)。
- 叠加层设置新增「确认中文本」勾选框(默认勾选, 取消后不显示"正在确认名单中…")。
- 检测到黑名单玩家时的比对本优化(300 条名单 × 201 昵称: 约 100 ms → 约 1 ms)。
- 新增详细排查日志(各阶段耗时、地图探测耗时、比对详情、UI 更新时间), 便于定位漏报。
- **改用 Apache License 2.0 许可**: 仓库新增 `LICENSE`(许可全文)与 `NOTICE`(作者信息 /
  第三方组件 / 免责声明); 安装版与绿色版的程序目录里也会放入这两个文件。
  **1.0 版同样采用该许可**(1.0 源码在仓库的 `1.0` 分支)。
